# Post 8-37: Data Insight Artifact Materialization

## Status

Done.

## Goal

Persist successful data insight skill outputs as real workspace artifacts.

This continues the old-product skill migration inside the new product framework: Agent skill -> structured output contract -> workspace artifact -> existing frontend artifact/query/export paths.

## Backend Change

The existing `data::execute` path now normalizes output contracts for data insight skills that previously returned raw JSON only.

Successful output includes:

```text
status=success
has_data=true
adapter_status=manual_input
data_readiness=user_provided | calculated_from_defaults
summary=...
```

Missing required user input becomes:

```text
status=deferred
has_data=false
adapter_status=user_input_required
data_readiness=missing_user_input
summary=...
```

Specific rules:

- `data_anomaly_diagnosis` needs at least three numeric points and defers without them.
- `data_trend_forecast` needs at least two numeric points and defers without them.
- `data_customer_segmentation` can use deterministic defaults and discloses them as `calculated_from_defaults`.
- `data_competitor_analysis` needs `our_product`; missing competitors use deterministic competitors and are disclosed as `calculated_from_defaults`.
- `data_ab_test_analyzer` keeps the existing validation contract for sample sizes and conversion counts.

## Workspace Artifact Change

`WorkspaceApi::materialize_agent_content_artifact` now supports:

- `data_anomaly_diagnosis` -> `artifactType=data_anomaly_report`
- `data_trend_forecast` -> `artifactType=data_trend_forecast_report`
- `data_customer_segmentation` -> `artifactType=data_customer_segmentation_report`
- `data_competitor_analysis` -> `artifactType=data_competitor_report`
- `data_ab_test_analyzer` -> `artifactType=data_ab_test_report`

Artifacts are markdown, inline, generated by `agent_session`, and use:

```text
metadata.kind=agent_generated_content
metadata.contentCategory=data
```

## API / SSE Contract

No new HTTP route was added.

The existing `workspace_artifact_created` SSE event is reused. `API_DOCS/app.md` and `API_DOCS/sse.md` document the data insight artifact types and the deferred behavior when required input is missing.

## User-Visible Change

Users can ask the data worker for anomaly diagnosis, trend forecast, customer segmentation, competitor analysis, or A/B test analysis. When backend input is sufficient and the skill succeeds, the output can appear in the workspace artifact list/detail/export flow.

If series or experiment input is missing where required, the backend returns `deferred` or validation error and does not create a fake data insight artifact.
