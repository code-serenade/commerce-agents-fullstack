# Post 8-133：电商工作台壳层与真实路由对齐

状态：done

## 本次目标

本轮不新增后端 API，也不新增假的功能入口，而是把已经存在的电商业务页面统一收进 Agent Chat 的工作台壳层：

- 问答、能力介绍、商品、活动、工作区、平台连接、审批、运营、能力包和交付物页面都使用同一套 `AgentChatShell`。
- 左侧历史对话、功能导航、管理与复盘在业务页之间保持可见，避免演示时切到业务页面后丢失历史对话入口。
- 当前路由属于功能导航或管理复盘时，对应折叠分区自动展开并高亮当前入口。
- 用户仍可以手动折叠分区，页面继续使用同事给的 `SidebarShell` 框架。

## 修改范围

- `frontend/apps/web/src/layouts/AppLayout.tsx`
  - 将电商业务页统一纳入 `AgentChatShell`。

- `frontend/apps/web/src/shell/AgentChatShell.tsx`
  - 增加 route group 判断。
  - 功能导航 / 管理与复盘分区按当前路由自动展开。
  - 移动端功能导航补齐概览和运营入口。
  - 非问答页面顶部标题改为当前功能入口名称，问答页继续显示当前会话标题。

## 产品内核变化

- 后端内核、SSE、Agent skill、API 和数据库本轮没有改动。
- 前端壳层更贴近“电商虚拟员工工作台”：用户在问答和业务页面之间切换时，仍处于同一产品上下文。

## 用户可感知变化

- 用户从问答跳到商品、活动、审批、工作区、能力包等页面时，左侧仍能看到历史对话和功能导航。
- 当前所在功能会在左侧对应分区自动展开，用户不会找不到自己在哪个业务模块。
- 功能导航和管理复盘仍可折叠，避免左侧长期铺满。
- 移动端功能导航入口更完整，包含概览和运营相关页面。
