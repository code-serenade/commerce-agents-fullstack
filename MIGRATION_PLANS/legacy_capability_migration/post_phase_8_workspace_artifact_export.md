# Post 8-15：工作区交付物导出能力

## 迁移目标

把旧产品“回答原文 / 报告导出”的能力迁到新产品后端 `workspace_artifacts` 体系里。前端不再只复制页面已有文本，而是调用后端导出接口，拿到带格式、文件名、MIME 和 warning 的导出结果。

## 产品内核变化

- 交付物成为可导出的正式后端资源。
- Agent 最终报告、搜索证据、人工交付物都可以沿用同一个导出入口。
- 当前阶段只导出数据库已经沉淀的 `content` 或 `preview`，不伪造对象存储、OCR 或二进制解析结果。

## 后端变化

- `WorkspaceApi::export_artifact` 新增交付物导出业务方法。
- 新增 `GET /api/app/workspaces/{workspaceId}/artifacts/{artifactId}/export`。
- 支持 `markdown`、`text`、`json` 三种导出格式。
- archived artifact 按不存在处理。
- 非 inline 存储会返回 warning，明确说明对象存储正文未读取。
- `API_DOCS/app.md` 已同步接口说明。

## 前端变化

- 工作区交付物详情面板新增真实导出查询。
- 详情内容优先展示后端导出的 `content`。
- 新增“复制导出”和“下载导出”操作。
- 展示导出格式、导出字数、导出文件名和 warning。

## 用户可感知变化

用户进入“执行工作区 -> 交付物”后，选中一个交付物，可以：

- 查看后端导出后的正式内容。
- 点击“复制导出”复制完整导出文本。
- 点击“下载导出”下载后端返回文件名对应的 `.md`、`.txt` 或 `.json` 文件。
- 如果该交付物只有预览或对象存储引用，界面会显示后端 warning，用户能知道当前导出是否完整。

## 验收口径

- 导出接口必须走 JWT 和工作区归属校验。
- 导出结果必须来自后端 `workspace_artifacts`。
- 不允许前端生成假导出。
- 不读取对象存储的阶段性限制必须明确暴露给用户。
