# Post 8-32: Accounting Artifact Materialization

## Status

Done.

## Goal

Persist successful core accounting skill outputs as real workspace artifacts.

This keeps accounting migration inside the new product framework instead of creating a separate financial reporting system.

## Backend Change

The following accounting skills now expose an explicit materialization-friendly output contract:

- `accounting_cost_calc`
- `accounting_profit_analysis`
- `accounting_roi_calc`
- `accounting_budget_plan`

Successful output includes:

```text
status=success
has_data=true
adapter_status=manual_input
summary=...
```

When defaults are used, the output includes:

```text
data_readiness=calculated_from_defaults
```

When required financial input is missing, the skill returns `status=deferred`, so the product does not create fake financial reports.

## Workspace Artifact Change

`WorkspaceApi::materialize_agent_content_artifact` now supports:

- `accounting_cost_calc` -> `artifactType=accounting_cost_report`
- `accounting_profit_analysis` -> `artifactType=accounting_profit_report`
- `accounting_roi_calc` -> `artifactType=accounting_roi_report`
- `accounting_budget_plan` -> `artifactType=accounting_budget_plan`

Artifacts are markdown, inline, generated by `agent_session`, and use:

```text
metadata.kind=agent_generated_content
metadata.contentCategory=accounting
```

## API / SSE Contract

No new HTTP route was added.

The existing `workspace_artifact_created` SSE event is reused. `API_DOCS/app.md` and `API_DOCS/sse.md` document the accounting report artifact types and the deferred behavior when required input is missing.

## User-Visible Change

Users can ask the accounting worker for cost calculation, profit analysis, ROI calculation, or budget planning. When the backend successfully computes the result, the report can appear in the workspace artifact list/detail/export flow.

If required financial input is missing, the backend returns `deferred` and no accounting report artifact is created.
