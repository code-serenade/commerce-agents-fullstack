# 1/8 到 3/8 已完成迁移小报告

当前总计划共 8 个开发项，已完成第 3/8 个。

## 一、问答策略 metadata 与后端路由事件

产品内核底层变化：

回答策略不再只是前端拼进 prompt 的文字，而是作为结构化 `metadata.strategy` 进入 Agent 运行时。后端可以基于策略做真实路由，并通过 SSE 返回 `route_decided` 事件。

后端变化：

SSE 请求支持策略 metadata；Agent runtime、commander routing 能读取策略；后端会输出真实路由事件。

前端变化：

前端策略选择会随请求发送到后端；右侧过程面板和时间线会展示后端返回的路由结果。

用户可感知变化：

用户选择“协同/快速/深度”等回答策略后，系统不再只是改提示词，而是由后端真正识别策略并决定由哪个虚拟员工或协作流程处理。

## 二、Skill 执行与 SSE 可视化

产品内核底层变化：

Skill 调用从后端内部执行记录，升级为 Agent 运行时可观察事件。能力调用、执行结果、失败、需审批等状态都可以通过 SSE 传给前端。

后端变化：

Worker 会解析并执行 skill 请求；执行前输出 `skill_requested`，执行后输出 `skill_result`；结果包含状态、摘要、错误、执行模式、风险等级、是否需要审批。

前端变化：

前端过程面板支持展示真实 skill 事件，不再伪造“工具调用中”。时间线和运行详情卡会显示能力名称、状态、结果和审批提示。

用户可感知变化：

用户提问后，如果后端调用了商品分析、平台操作、内容生成等能力，右侧会看到真实执行过程；高风险动作会提示需审批，不会误导用户以为已经自动完成。

## 三、产品知识与上下文绑定

产品内核底层变化：

Agent 问答可以绑定真实商品上下文。后端会根据当前登录用户读取可用商品和商品知识，把摘要注入 commander 和 worker 的认知上下文。

后端变化：

新增商品上下文聚合服务；SSE 请求支持 `metadata.context.productIds` 和 `metadata.context.contextRefs`；后端校验用户与商品归属后，装配商品、知识、来源数量和上下文摘要，并输出 `context_loaded` 事件。

前端变化：

问答输入区会读取后端 active 商品，展示商品 chip；用户选择商品后，请求会带上商品上下文；右侧过程面板显示后端真实加载到的商品和知识数量。

用户可感知变化：

用户可以在问答前选择相关商品，之后模型回答会基于后端读取到的商品名称、平台、类目、品牌、价格、描述和知识摘要；如果没选商品，系统不会假装知道商品信息。

## 总结

前三项迁移已经把问答策略、Skill 执行、商品知识上下文三条核心链路从“前端展示/提示词层面”推进到“后端真实运行时能力”。前端现在主要负责选择、展示和交互；后端负责策略识别、能力执行、上下文装配和过程事件输出。
