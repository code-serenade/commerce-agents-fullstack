# Post 8-31: Data Analysis Artifact Materialization

## Status

Done.

## Goal

Persist successful native data analysis skill outputs as real workspace artifacts.

This follows the Post 8-30 `data_dashboard` path and keeps the work inside the new product framework instead of adding a second report system.

## Backend Change

The following data skills now expose an explicit successful output contract when user data is present:

- `data_funnel_analysis`
- `data_channel_roi`
- `data_refund_decomposition`

Successful output includes:

```text
status=success
has_data=true
data_readiness=user_provided
adapter_status=manual_input
summary=...
```

Missing input data remains `deferred`, so the product does not create fake data reports.

## Workspace Artifact Change

`WorkspaceApi::materialize_agent_content_artifact` now supports:

- `data_funnel_analysis` -> `artifactType=data_funnel_report`
- `data_channel_roi` -> `artifactType=data_channel_roi_report`
- `data_refund_decomposition` -> `artifactType=data_refund_report`

Artifacts are markdown, inline, generated by `agent_session`, and use:

```text
metadata.kind=agent_generated_content
metadata.contentCategory=data
```

## API / SSE Contract

No new HTTP route was added.

The existing `workspace_artifact_created` SSE event is reused. `API_DOCS/app.md` and `API_DOCS/sse.md` document the new data report artifact types and the deferred behavior when input data is missing.

## User-Visible Change

When users ask the data worker for funnel analysis, channel ROI ranking, or refund decomposition and provide enough data, the result can become a workspace deliverable. Users can later find the report through the existing artifact list/detail/export flow.

If no real user data is provided, the backend returns `deferred` and no report artifact is created.
