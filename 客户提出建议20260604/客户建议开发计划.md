# 客户建议开发计划（2026-06-04 批次）

## 需求摘要

本批客户建议覆盖注册、资料库、商品/活动低成本体验、聊天输入面板、任务过程可读性、Agent 输出质量、历史上下文浓缩与实训复盘结构。

## 产品判断

1. 注册补充院校和队伍名应落在当前项目 App 用户资料，不改外部认证服务。
2. 资料库、上传资料、聊天上下文选择应打通为同一套资料来源，避免用户重复上传。
3. 商品/活动空状态不应只提示“暂无”，应提供直接创建和示例导入，让学生低成本开始实训。
4. AI 补全商品/活动信息必须是“生成草稿，学生审核后保存”，不能直接入库。
5. Agent 回答问题优先通过后端用户可见清洗、prompt 和历史上下文预算治理解决，不在前端硬替换正文。

## 开发拆分

### 1. 注册体验

- 将注册表单中的“用户名”改为“账号”，明确 3-32 位，支持英文、数字、下划线和连字符。
- 新增院校、队伍名字段到项目 App 用户资料。
- 首次进入 App 注册用户资料时保存院校和队伍名。

测试计划：
- 中文账号被前端校验拦截并展示账号规则文案。
- 合法账号可提交。
- 新老 App 用户都能正常注册/进入，老数据缺少院校队伍字段不报错。

### 2. 聊天输入面板

- 保留点击面板外关闭。
- 给商品、活动、资料、设置等输入面板统一增加右上角关闭按钮。

测试计划：
- 点击关闭按钮后 active panel 变为空。
- 点击面板内部其它按钮不会误关闭。

### 3. 资料库互通

- 恢复并强化“管理资料库”入口。
- 上传资料、资料库 attach、当前轮资料选择使用同一套 conversation file/source ref。

测试计划：
- 空资料库仍显示管理入口。
- 从资料库选择文件后，当前轮 source refs 包含 `conversation_file:{id}`。

### 4. 商品/活动低成本体验

- 未选商品面板和商品库空状态增加“添加商品”入口。
- 商品库、活动库提供示例模板导入，点击后复制到当前用户数据。
- 防止快速双击造成重复创建。

测试计划：
- 空状态展示添加入口和示例模板。
- 示例导入后列表刷新并可被聊天选中。
- 快速双击只创建一条记录。

### 5. AI 补全草稿

- 新增商品草稿/活动草稿能力。
- 用户填少量字段，AI 生成结构化草稿，前端填回表单，用户审核后保存。

测试计划：
- AI 返回草稿不直接入库。
- 非法 enum/status 被服务端规整或拒绝。
- 用户确认保存后才创建商品/活动。

### 6. 多岗位上限

- 将手动多岗位选择上限配置化，默认提升到 8 或 10。
- UI 提醒选择过多会更慢。

测试计划：
- 第 7、8 个岗位可选择。
- 超过上限时前后端均有明确提示。

### 7. 任务过程可读性

- 分析过程/任务过程面板正文提升到接近回答正文的字号和行高。
- 状态标签、时间戳保持小字号。

测试计划：
- 关键内容不截断。
- 桌面和移动宽度不重叠。

### 8. Agent 输出质量

- 扩展后端用户可见清洗策略，过滤 `context.selected_summary`、`context.combined_summary`、`worker.assignment.input.*`、`role_output`、`sourceMap`、`memoryBudget` 等内部字段。
- 优化复盘类回答结构：结论摘要、直播数据结论、经营问题诊断、整改优先级、落地优化建议、下次复盘字段。

测试计划：
- 纯单元测试输入内部字段，断言输出不包含英文变量名且保留业务含义。
- 复盘类输出标题顺序稳定，同类内容聚合。

### 9. 历史上下文浓缩

- 保留最近原文窗口。
- 维护结构化事实、决策、约束、未决问题。
- 按本轮问题检索少量历史片段。
- 输出 source map 供 context-preview 和调试使用，但不泄漏给最终回答。

测试计划：
- 构造长会话，断言相关历史被选中、无关商品不注入、字符预算不超限。
- “继续刚才”能引用最近轮原文。

## 推荐验证组合

- 前端：注册、面板、资料/商品选择使用组件和 Hook 测试。
- 后端：注册扩展、示例导入幂等、草稿接口用 service/API 单测。
- Agent：用户可见清洗、复盘结构、上下文预算用纯单元测试和 context-preview。
- 浏览器：只对聊天主界面做一次桌面/移动截图验证。
- 真实 LLM：最多 2 条冒烟，不进入常规回归。

### 历史上下文优化参考

客户提出“用较少 token 带上历史对话上下文”的方向，与 2025-2026 年 Agent memory 的主流做法一致：不推荐把完整历史长期塞入 prompt，而是把最近原文窗口、长期结构化记忆和检索召回分层组合。

参考资料：

1. Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory，arXiv 2025-04-28，提出抽取、合并、检索显著记忆，并报告相比全量上下文显著降低 token 成本和延迟：https://arxiv.org/abs/2504.19413
2. A-MEM: Agentic Memory for LLM Agents，arXiv 2025-02-17，强调类似 Zettelkasten 的动态记忆组织和上下文感知检索：https://arxiv.org/abs/2502.12110
3. Hierarchical Memory for High-Efficiency Long-Term Reasoning in LLM Agents，2025-07，强调分层记忆以提升长程推理效率：https://huggingface.co/papers/2507.22925

建议后续实现：

1. 短期层：保留最近 N 轮原文，专门支持“继续刚才”“照上面改”。
2. 结构层：按事实、决策、约束、偏好、未决问题、商品/活动实体维护可更新 memory cards。
3. 检索层：用当前问题、已选商品/活动/资料和任务类型召回少量相关记忆。
4. 防泄漏层：source map、命中分数、内部 key 只给调试和 context-preview，不进入最终回答。
5. 评估层：用长会话夹杂多商品、多活动、多轮修正的固定样例做单元测试，断言相关历史被召回、无关实体不注入、预算不超限。
